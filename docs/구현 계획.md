# 구현 계획 — 팀 편성 웹 앱

상세한 태스크 단위 실행 기록은 [docs/superpowers/plans/2026-10-26-team-formation-app.md](superpowers/plans/2026-10-26-team-formation-app.md)에 있다. 이 문서는 그 계획을 사람이 읽기 쉽게 요약한다.

## 모듈 구성

| 파일 | 역할 |
|---|---|
| `rules.py` | 팀 규칙 판정 순수 함수(DB/Streamlit 의존성 없음) — 자동 테스트의 핵심 대상 |
| `auth.py` | bcrypt 비밀번호 해시/검증 |
| `ai_assign.py` | OpenRouter 호출, 1차→2차→3차 폴백, 전체 타임아웃 강제, 3차 실패 시 자체 배정 |
| `db.py` | SQLAlchemy 엔진(1회 생성) + 모든 DB 쿼리/트랜잭션 |
| `streamlit_app.py` | 화면(로그인/학생/관리자), Streamlit `key` 지정 |
| `schema.sql` | `tf_` 테이블 정의 |
| `tests/` | `rules.py`, `ai_assign.py`에 대한 pytest |

## 진행 순서 (12개 태스크)

1. 저장소 뼈대(venv, requirements.txt, .gitignore, .env.example) + GitHub 저장소 생성
2. `rules.py` 1부 — 필수 포함 역할 자리 계산, 지원 가능 판정, `result` 접두어 검증
3. `rules.py` 2부 — 최종 배정 검증(2.5절 4항 5가지), 전수 탐색 배정
4. `auth.py` — bcrypt 해시/검증
5. `ai_assign.py` — 폴백과 전체 타임아웃 강제(가짜 응답으로 테스트)
6. `schema.sql` + `db.py` 읽기/초기화 레이어 — **Supabase 프로젝트 생성이 선행 조건**
7. `db.py` 학생 액션 — 지원/투표, 승인 직전 재검사, 재지원 차단, 투표자 동적 변경
8. `db.py` 관리자 액션 — 모집 마감(1인팀 해체), AI 배정, 확정
9. Streamlit UI — 로그인/학생 화면(`st.fragment(run_every="5s")`로 팀 목록 자동 갱신)
10. Streamlit UI — 관리자 화면(명단/마감/AI 배정/확정)
11. DB 일시정지 방지(GitHub Actions) + README/PRD/구현계획 문서
12. 부록 1~3 시나리오 전체 수동 검증 + 배포(Supabase/OpenRouter 키 확인, Streamlit Community Cloud)

각 태스크는 구현 전 실패하는 테스트(또는 재현 시나리오)를 먼저 만들고, 구현 후 통과를 확인한 뒤 커밋하는 순서로 진행했다. DB가 필요한 태스크(6 이후)는 실제 Supabase에 직접 연결해 검증했고, UI 태스크(9, 10)는 로컬 `streamlit run`과 브라우저로 버튼을 직접 눌러 확인했다.

## 구현 중 찾은 주요 문제와 대응

README.md 6항에 근거와 함께 정리되어 있다. 핵심만 요약하면: DB 시퀀스 리셋 누락, 마감 표시 초기화 누락, `st.rerun()`이 결과 메시지를 지우는 문제, `st.fragment` 안에 액션 버튼을 두면 안 되는 문제, pandas 순환 임포트 레이스 — 전부 수동 시나리오 검증 중 발견해 테스트/재현 후 고쳤다.
